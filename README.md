# RIX STORM PANEL 2.4 — Automatic VPS Setup

## اصلاحات این نسخه

- فرم افزودن سرور به سه ورودی اصلی کاهش یافته و توکن Agent، آدرس HTTPS و پورت‌های پیش‌فرض خودکار ساخته می‌شوند.
- دستور نصب اختصاصی هر سرور از داخل پنل تولید می‌شود؛ نصب‌کننده روی VPS، Xray-core و Agent را نصب می‌کند، TLS را با گواهی قابل تمدید آماده می‌کند و کلیدهای Reality را تولید می‌کند.
- با فشردن «آزمایش اتصال»، تنظیمات TLS و Reality از Agent دریافت و در پنل ذخیره می‌شوند؛ نیازی به کپی دستی کلیدها نیست.
- هنگام ساخت کاربر، انتخاب پروتکل کافی است؛ حالت خودکار برای VLESS، VMess، Trojan و Shadowsocks از پیش‌فرض‌های سازگار استفاده می‌کند. تنظیمات انتقال اضافی در بخش پیشرفته باقی می‌مانند.
- Agent برای دستور `xray api adi` یک شیء inbound منفرد می‌فرستد و ورودی‌های ساخته‌شده را پس از راه‌اندازی مجدد Xray بازیابی می‌کند.

**محدودیت مهم:** تست محلی جایگزین اتصال به VPS واقعی نیست. معتبر بودن نهایی TLS/Reality، بازبودن پورت‌ها، نسخه Xray نصب‌شده، قوانین فایروال و مسیر شبکه باید روی سرور مقصد بررسی شود. هیچ نرم‌افزاری را نمی‌توان صادقانه «بدون باگ یا قطعی تضمینی» اعلام کرد.

نسخه بازطراحی‌شده و تخت برای مدیریت کاربران Xray. تمام فایل‌های پروژه در ریشه ZIP هستند و پوشه اضافی داخل ZIP وجود ندارد.

فایل‌های `preview-dashboard-dark.png` و `preview-dashboard-light.png` تصاویر جداگانه تم تیره و روشن‌اند؛ تصاویر `preview-nodes.png`، `preview-clients.png`، `preview-mobile.png` و `preview-subscription.png` نیز فقط پیش‌نمایش رابط با اطلاعات ساختگی هستند، نه خروجی سرور واقعی.

> **نکته درباره داده‌ها:** این بسته را ابتدا در یک سرویس آزمایشی Railway و Volume جداگانه بررسی کن. پیش از جایگزینی نسخه فعال، از دیتابیس و متغیرهای محیطی فعلی نسخه پشتیبان بگیر؛ سازگاری مستقیم دیتابیس با نسخه‌های قبلی بدون بررسی ساختار آن تضمین‌شده نیست.

## این نسخه چه کار می‌کند؟

- ساخت کاربر با انتخاب پروتکل، حجم و اعتبار؛ روش انتقال و امنیت در حالت عادی به‌صورت خودکار انتخاب می‌شوند.
- پشتیبانی از پروتکل‌های **VLESS، VMess، Trojan و Shadowsocks** با محدودیت‌های سازگار هرکدام.
- انتقال‌های TCP، WebSocket، gRPC و XHTTP برای ترکیب‌های پشتیبانی‌شده.
- برای هر کاربر یک inbound و پورت اختصاصی در Xray ایجاد می‌کند؛ خاموش/روشن‌کردن و حذف کاربر نیز از طریق Agent به Xray فرستاده می‌شود.
- صفحه اشتراک خصوصی، نمایش لینک/کانفیگ و QR Code.
- رابط فارسی راست‌چین با تم تیره و روشن.
- رمزگذاری اطلاعات حساس ذخیره‌شده و محافظت CSRF برای فرم‌ها.

**حجم و انقضا:** انقضای زمانی به شکل خودکار بررسی می‌شود. این نسخه هنوز شمارنده زنده مصرف ترافیک Xray را پیاده نکرده است؛ مقدار مصرف فعلاً دستی ثبت می‌شود و نباید به‌عنوان اندازه‌گیری زنده حجم در نظر گرفته شود.

## معماری ساده

دو بخش لازم است:

1. **پنل مدیریتی** روی Railway اجرا می‌شود. صفحه وب، کاربران، اشتراک‌ها و دیتابیس را نگه می‌دارد.
2. **Xray-core و RIX Agent** روی یک VPS واقعی که قرار است ترافیک VPN را عبور دهد اجرا می‌شوند. Agent به شکل احراز هویت‌شده، درخواست ساخت/حذف inbound را به API محلی Xray می‌فرستد.

Railway فقط محل اجرای پنل است؛ آن را به‌جای VPS واقعی VPN فرض نکن. برای ارتباط کلاینت‌ها باید روی VPS پورت‌های انتخاب‌شده باز باشند و دامنه/IP داخل کانفیگ واقعاً به همان سرویس برسد.

## بخش اول — استقرار پنل روی Railway

1. این فایل‌ها را از ZIP استخراج کن یا محتویات را در ریشه مخزن GitHub خودت قرار بده؛ `Dockerfile` در ریشه است.
2. در Railway یک سرویس جدید از repository ایجاد کن. Railway به‌صورت خودکار Dockerfile را تشخیص می‌دهد.
3. در بخش **Variables** متغیرهای زیر را تعریف کن:

| Variable | چه مقداری وارد کنم؟ |
|---|---|
| `APP_ENV` | `production` |
| `APP_NAME` | `RIX STORM PANEL 2.4` |
| `SECRET_KEY` | رشته تصادفی محرمانه حداقل ۴۰ کاراکتری؛ نمونه امن را با `python -c "import secrets; print(secrets.token_urlsafe(48))"` بساز |
| `DATA_ENCRYPTION_KEY` | کلید Fernet؛ با دستور `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` بساز |
| `ADMIN_USERNAME` | نام ورود مدیر، مثلاً `admin` |
| `ADMIN_PASSWORD` | رمز قوی و یکتا با حداقل ۱۶ کاراکتر |
| `PUBLIC_BASE_URL` | دامنه عمومی HTTPS سرویس Railway، بدون `/` پایانی؛ مانند `https://your-panel.up.railway.app` |
| `DATA_DIR` | `/data` |
| `DATABASE_URL` | خالی بگذار تا SQLite داخل `/data/rix_storm.db` استفاده شود |
| `SESSION_MAX_AGE_SECONDS` | `28800` |

4. در Railway برای سرویس، یک **Volume** بساز و به مسیر `/data` وصل کن. بدون Volume، فایل دیتابیس SQLite ممکن است با استقرار مجدد از بین برود.
5. در بخش Networking دامنه عمومی برای پنل بساز، سپس مقدار دقیق آن را در `PUBLIC_BASE_URL` قرار بده و Redeploy کن.
6. پنل را باز کن و با `ADMIN_USERNAME` و `ADMIN_PASSWORD` وارد شو.

`PORT` را دستی وارد نکن؛ دستور راه‌اندازی از متغیر `PORT` خود Railway استفاده می‌کند.

**کلیدها را در فایل GitHub یا چت عمومی قرار نده.** اگر `DATA_ENCRYPTION_KEY` را بعداً عوض کنی، اطلاعات محرمانه‌ای که با کلید قبلی ذخیره شده‌اند دیگر رمزگشایی نمی‌شوند؛ آن را در جای امن نگه دار.

## بخش دوم — افزودن و نصب خودکار VPS

این مرحله را فقط یک‌بار برای هر VPS انجام بده.

### پیش‌نیازهای لازم

- VPS تازه با **Debian 12** یا **Ubuntu 22.04/24.04** و دسترسی `sudo`.
- یک دامنه عمومی مانند `vpn.example.com` که رکورد DNS آن به IP همین VPS اشاره کند.
- پورت‌های ورودی TCP **80 و 443** برای گرفتن و تمدید گواهی HTTPS.
- بازه TCP/UDP **20000–20100** برای اتصال کاربران. این بازه را هم در فایروال VPS و هم در Firewall/Security Group ارائه‌دهنده باز کن.
- در Railway مقدار `PUBLIC_BASE_URL` باید آدرس HTTPS عمومی پنل باشد؛ در غیر این صورت دستور نصب ممکن است لینک اشتباه بسازد.

### مراحل

1. در پنل وارد **سرورها** شو و نام سرور، دامنه و در صورت نیاز Proxy IP را ثبت کن. IP را به‌جای دامنهٔ اصلی وارد نکن؛ IP واسط در فیلد Proxy IP قرار می‌گیرد.
2. در کارت سرور روی **کپی دستور نصب** بزن.
3. با SSH به همان VPS وصل شو و دستور را در محیط کاربر `root` اجرا کن. اگر با کاربر عادی وصل شده‌ای، ابتدا `sudo -i` یا `su -` را اجرا کن. نصب‌کننده بسته‌های موردنیاز را نصب می‌کند.
4. نصب‌کننده یک Xray جداگانه با سرویس `rix-storm-xray`، Agent با سرویس `rix-storm-agent`، Nginx و گواهی خودکار TLS آماده می‌کند. تنظیمات API هستهٔ Xray را فقط روی loopback نگه می‌دارد، یک جفت کلید Reality و Short ID واقعی تولید می‌کند و تلاش می‌کند قوانین UFW را نیز اضافه کند.
5. به پنل برگرد و **آزمایش اتصال و همگام‌سازی خودکار** را بزن. پنل تنظیمات TLS و Reality را از Agent دریافت و ذخیره می‌کند.
6. در فایروال ابری VPS نیز مطمئن شو پورت 80/TCP، پورت 443/TCP و بازه انتخاب‌شده برای TCP و UDP باز هستند. نصب‌کننده نمی‌تواند Firewall/Security Group داخل پنل شرکت میزبان را تغییر دهد.

### ایمنی و محدودیت نصب

- نصب‌کننده اگر پورت 80 یا 443 در حال استفاده باشد متوقف می‌شود؛ سرویس وب موجود را خودکار بازنویسی نمی‌کند. در این حالت یا از VPS تازه استفاده کن یا نصب را با مدیر سرور هماهنگ کن.
- گواهی خودکار به دامنهٔ عمومی صحیح و در دسترس‌بودن پورت 80 نیاز دارد. اگر DNS هنوز منتشر نشده باشد، پروکسی/CDN درخواست ACME را مسدود کند یا فایروال بسته باشد، مرحلهٔ گواهی شکست می‌خورد.
- Xray در سرویس مجزای `rix-storm-xray` اجرا می‌شود و فایل کانفیگ سرویس قدیمی Xray را overwrite نمی‌کند؛ بااین‌حال VPS تازه برای جلوگیری از تداخل پورت‌های کاربران توصیه می‌شود.
- Private Key مربوط به Reality در فایل محافظت‌شدهٔ محیطی VPS ذخیره می‌شود و از کانال HTTPS احراز هویت‌شده به پنل برمی‌گردد. آن را در چت عمومی یا مخزن کد قرار نده.
- برای دسترسی از طریق Proxy IP یا Port Forwarding، واسط باید همهٔ پورت‌های انتخاب‌شده و پروتکل‌های TCP/UDP موردنیاز را درست عبور دهد.

## بخش سوم — انتخاب پروتکل هنگام ساخت کاربر

پس از یک تست اتصال موفق، از **کاربران و اشتراک‌ها** فقط نام، پروتکل، سهمیه و مدت اعتبار را وارد کن. حالت خودکار این انتخاب‌ها را اعمال می‌کند:

| پروتکل | پیش‌فرض خودکار | نکته |
|---|---|---|
| VLESS | Reality روی TCP | کلیدها و Short ID از نصب‌کننده می‌آیند. |
| VMess | TLS روی TCP | از گواهی دامنهٔ نصب‌شده استفاده می‌کند. |
| Trojan | TLS روی TCP | به گواهی معتبر نیاز دارد. |
| Shadowsocks | TCP، بدون TLS در سطح Xray | رمز مستقل برای هر کاربر ساخته می‌شود. |

گزینه‌های WebSocket، gRPC، XHTTP و Flow در «تنظیمات اتصال پیشرفته» هستند. ترکیب‌های ناسازگار یا فاقد پیش‌نیاز توسط پنل رد می‌شوند. پیش‌فرض TLS برای انتقال‌های WebSocket/gRPC/XHTTP مناسب‌تر است؛ Reality در این نسخه فقط برای VLESS و به‌جز WebSocket قابل استفاده است.

## بخش چهارم — ساخت کاربر

1. وارد **کاربران و اشتراک‌ها** شو.
2. نام و سرور را انتخاب کن.
3. پروتکل را مشخص کن: VLESS، VMess، Trojan یا Shadowsocks.
4. حالت خودکار را نگه دار؛ پنل با توجه به پروتکل انتخاب‌شده و اطلاعات همگام‌شدهٔ سرور، تنظیمات پایه را انتخاب می‌کند. در صورت نیاز تنظیمات انتقال در بخش پیشرفته است.
5. حجم را به GB و اعتبار را به روز وارد کن. صفر یعنی بدون محدودیت/انقضا در منطق پنل.
6. ساخت کاربر را بزن. پنل ابتدا درخواست inbound را به Agent می‌فرستد و سپس رکورد را ذخیره می‌کند. اگر API در دسترس نباشد، پیام خطا نمایش داده می‌شود.
7. لینک اشتراک را کپی کن یا ساب‌پنل کاربر را باز کن.

## عیب‌یابی سریع

- **اتصال Agent برقرار نمی‌شود:** اول مطمئن شو دستور نصب بدون خطا پایان یافته، گواهی دامنه معتبر است و سرویس‌های `rix-storm-agent`، `rix-storm-xray` و `nginx` فعال‌اند. سپس آدرس و توکن ثبت‌شده در پنل را بررسی کن.
- **Xray کاربر را نپذیرفت:** `sudo systemctl status rix-storm-xray rix-storm-agent` را بررسی کن. API داخلی این نسخه روی `127.0.0.1:19085` است؛ آن را در فایروال عمومی باز نکن.
- **کاربر ثبت شد ولی وصل نمی‌شود:** پورت اختصاصی را در فایروال VPS و پنل شبکه باز کن؛ Host/Proxy IP، SNI، TLS certificate و پارامترهای Reality باید واقعاً با سرور هماهنگ باشند.
- **Reality خطا می‌دهد:** public/private key، Short ID و SNI را با مقادیر واقعی یکسان کن.
- **پس از Redeploy اطلاعات ناپدید شده:** Volume باید روی `/data` متصل باشد و `DATA_DIR=/data` تنظیم شده باشد.
- **حجم اشتباه است:** آمار زنده در این نسخه هنوز پیاده نشده؛ مقدار مصرف نمایش‌داده‌شده دستی ثبت می‌شود.

## فایل‌های مهم (همگی در ریشه پروژه)

- `main.py` — پنل وب و عملیات مدیریتی
- `protocols.py` — اعتبارسنجی و تولید inbound/link
- `xray_agent.py` — Agent محافظت‌شده کنار Xray
- `agent_client.py` — اتصال پنل به Agent از طریق HTTPS
- `models.py`, `database.py`, `security.py` — دیتابیس و امنیت
- `Dockerfile`, `requirements.txt`, `start.sh` — استقرار Railway
- `install_xray_agent.sh` — نصب خودکار Xray، Agent، TLS/Nginx و تنظیمات Reality؛ `xray-agent.service.example` و `Caddyfile.example` فقط نمونه‌های قدیمی/جایگزین هستند
